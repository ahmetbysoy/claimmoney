    48→## 1. Bağlam ve Geçiş Özeti
    49→
    50→Mevcut **ClaimMoney** projesi, sunucu taraflı çalışan bir Tierflow mikro-yapı motoru üzerine kuruludur. `src/lib/engine/` altındaki 17 ana modül, 10 dedektör, 8 feature builder, 2 kitap servisi, 4 strateji modülü, 3 risk modülü, 2 execution modülü ve 2 performans modülü içerir.
    51→
    52→**BOZOK PRO v4.0**, bu motoru tamamen tarayıcı içine taşır. Sunucu taraflı işleme sona erer; tüm L2 veri işleme, dedektör çalıştırma, sinyal üretimi ve plan yönetimi bir **Inline Web Worker** içinde gerçekleşir. Frontend, mevcut shadcn/ui demo dashboard'ı yerine 8 panel koyu tema terminal arayüzüyle değiştirilir.

    82→## 2. Mimari
    83→
    84→```mermaid
    85→flowchart TB
    86→  subgraph MainThread[Ana İş Parçacığı (UI)]
    87→    WS[WebSocket Manager] -->|cmd: book,trade,liq| Worker[Inline Web Worker]
    88→    Worker -->|state diff @200ms| Store[Zustand Store]
    89→    Store --> UI[8 Panel Terminal UI]
    90→    UI -->|armPlan, cancelPlan, config| Worker
    91→  end
    92→
    93→  subgraph WorkerThread[Web Worker (Motor)]
    94→    Worker --> RB[Ring Buffers]
    95→    RB --> BK[Order Book State]
    96→    RB --> FT[Feature Engine]
    97→    FT --> Det[Detector Registry - 16 Tip]
    98→    Det --> CE[Confluence Engine]
    99→    CE --> RG[Risk Gates]
   100→    RG --> RR[Net RR Calculator]
   101→    RR --> PSM[Plan State Machine]
   102→    PSM --> PP[Paper Performance Tracker]
   103→    PSM --> WH[Webhook Dispatcher]
   104→    Det --> RV[Regime Classifier]
   105→    RV --> NR[Narrative Generator]
   106→  end
   107→```
   108→
   109→### Temel Mimari Kurallar
   110→
   111→1. **Worker tek gerçeklik kaynağıdır** — tüm L2 veri işleme, sinyal üretimi, plan yönetimi worker içinde gerçekleşir
   112→2. **Typed array'ler zorunludur** — `Float64Array`, `Uint8Array`, `Uint16Array` ile tüm state, GC baskısını minimize eder
   113→3. **Ring buffer'lar sabit boyutludur** — trades (512), CVD (128), flow (64), liquidations (256), signals (128)
   114→4. **State sync 200ms throttled** — worker → main thread iletişimi diff tabanlı, 200ms aralıklı
   115→5. **Plan kullanıcı onayı gerektirir** — otomatik işlem yok; NEUTRAL → CANDIDATE → ARMED akışı
   116→6. **Tüm fiyatlar tick normalize edilir** — borsa tick size'ına göre yuvarlama zorunlu

   120→## 3. Inline Web Worker (P0)
   121→
   122→**Öncelik:** Kritik — Tüm motorun çalışma ortamı
   123→**Mevcut Referans:** `src/lib/engine/market-runtime.ts`, `src/lib/engine/tierflow-runtime.ts`
   124→
   125→### 3.1 State Yönetimi (Typed Arrays)
   126→
   127→Worker içi tüm durum, heap allocation olmadan typed array'lerde tutulur:
   128→
   129→```ts
   130→// worker-state.ts
   131→interface WorkerState {
   132→  // Order Book: 50 seviye (bid + ask)
   133→  bidPrices: Float64Array;   // [50]
   134→  bidQties: Float64Array;    // [50]
   135→  askPrices: Float64Array;   // [50]
   136→  askQties: Float64Array;    // [50]
   137→  prevBidPrices: Float64Array; // önceki frame (velocity için)
   138→  prevBidQties: Float64Array;
   139→  prevAskPrices: Float64Array;
   140→  prevAskQties: Float64Array;
   141→
   142→  // Ring Buffers
   143→  tradeRing: { prices: Float64Array; qties: Float64Array; sides: Uint8Array; ts: Float64Array; head: number; size: number }; // 512
   144→  cvdRing: { values: Float64Array; ts: Float64Array; head: number; size: number }; // 128
   145→  flowRing: { buyN: Float64Array; sellN: Float64Array; delta: Float64Array; ts: Float64Array; head: number; size: number }; // 64
   146→  liqRing: { sides: Uint8Array; prices: Float64Array; notional: Float64Array; ts: Float64Array; head: number; size: number }; // 256
   147→  signalRing: { types: Uint16Array; confs: Float64Array; dirs: Uint8Array; ts: Float64Array; head: number; size: number }; // 128
   148→}
   149→```
   150→
   151→### 3.2 Worker Mesaj Protokolü
   152→
   153→```ts
   154→// Worker'a gelen komutlar (main thread → worker)
   155→type WorkerCmd =
   156→  | { type: 'book'; bids: [number, number][]; asks: [number, number][]; ts: number; seq: number }
   157→  | { type: 'trade'; price: number; qty: number; side: 'buy' | 'sell'; ts: number }
   158→  | { type: 'liq'; side: 'buy' | 'sell'; price: number; notional: number; ts: number }
   159→  | { type: 'config'; cfg: WorkerConfig }
   160→  | { type: 'armPlan'; planId: string }
   161→  | { type: 'cancelPlan'; planId: string }
   162→  | { type: 'reset' };
   163→
   164→// Worker'dan çıkan mesajlar (worker → main thread)
   165→type WorkerMsg =
   166→  | { type: 'state'; diff: StateDiff; ts: number }
   167→  | { type: 'plan'; plan: PlanState }
   168→  | { type: 'signal'; signal: SignalRecord }
   169→  | { type: 'fill'; fill: FillRecord }
   170→  | { type: 'narrative'; text: string; regime: RegimeInfo }
   171→  | { type: 'error'; msg: string };
   172→```
   173→
   174→### 3.3 Diff Tabanlı State Sync
   175→
   176→Worker her 200ms'de bir state snapshot gönderir. Sadece değişen alanlar `StateDiff` içinde iletilir:
   177→
   178→```ts
   179→interface StateDiff {
   180→  bookChanged: boolean;
   181→  bestBid?: number; bestAsk?: number;
   182→  spreadBps?: number;
   183→  midPrice?: number;
   184→  tradesAdded: number;     // son sync'ten bu yana eklenen trade sayısı
   185→  signalsAdded: number;
   186→  planChanged: boolean;
   187→  regimeChanged: boolean;
   188→  regime?: RegimeInfo;
   189→  narrativeChanged: boolean;
   190→  narrative?: string;
   191→  // ... sadece değişen metrikler
   192→}
   193→```

   197→## 4. Plan Durum Makinesi (P0)
   198→
   199→**Öncelik:** Kritik — Kullanıcı etkileşimli işlem planlama
   200→**Mevcut Referans:** `src/lib/engine/strategy/decisionMachine.ts` (IDLE→ARMED→FIRED→COOLDOWN), `src/lib/engine/risk/tradePlanner.ts`
   201→
   202→### 4.1 Durumlar
   203→
   204→```ts
   205→type PlanState = 'NEUTRAL' | 'CANDIDATE' | 'ARMED';
   206→
   207→type Plan = {
   208→  id: string;
   209→  state: PlanState;
   210→  direction: 'LONG' | 'SHORT';
   211→  entry: number;
   212→  stopLoss: number;
   213→  takeProfit: number;
   214→  netRR: number;
   215→  confidence: number;
   216→  confluenceCount: number;
   217→  confluenceTypes: SignalType[];
   218→  createdAt: number;
   219→  ttl: number;              // varsayılan 30.000ms
   220→  expiresAt: number;
   221→  signalIds: string[];
   222→};
   223→```
   224→
   225→### 4.2 Geçiş Kuralları
   226→
   227→```mermaid
   228→stateDiagram-v2
   229→  [*] --> NEUTRAL
   230→  NEUTRAL --> CANDIDATE : confluence >= 3 && netRR >= 2.0 && riskGatePass
   231→  CANDIDATE --> ARMED : kullanıcı ARM butonu
   232→  CANDIDATE --> NEUTRAL : TTL sona erdi / yeni sinyal çelişiyor
   233→  ARMED --> NEUTRAL : kullanıcı CANCEL / TTL sona erdi / fill tamamlandı
   234→  ARMED --> NEUTRAL : fill tamamlandı (paper execution devralır)
   235→```
   236→
   237→- **CANDIDATE oluşturma koşulları:**
   238→  - En az **3 benzersiz sinyal tipi** aynı yönde, 30 saniye penceresi içinde
   239→  - **Net RR >= 2.0** (bölüm 7'ye bak)
   240→  - Tüm risk kapıları geçmiş (bölüm 5'e bak)
   241→
   242→- **Otomatik sonlanma:**
   243→  - TTL varsayılan **30 saniye**. Son 5 saniyede UI'da görsel uyarı
   244→  - Aynı yönde yeni CANDIDATE oluşturulmaz (30 saniye cooldown)
   245→
   246→- **ARM mekanizması:**
   247→  - Kullanıcı sadece CANDIDATE durumundaki planları onaylayabilir
   248→  - ARM butonu UI'de her zaman görünür (Panel 5 - LEVELS)
   249→  - ARM sonrası paper execution tetiklenir

   253→## 5. Risk Kapıları (P0)
   254→
   255→**Öncelik:** Kritik — Plan oluşturmadan önceki zorunlu kontrol
   256→**Mevcut Referans:** `src/lib/engine/strategy/filters.ts`
   257→
   258→Her CANDIDATE oluşturulmadan önce şu 5 kapıdan geçilmelidir. Herhangi biri başarısız olursa plan oluşturulmaz:
   259→
   260→| # | Kapı | Koşul | Başarısız Mesajı |
   261→|---|---|---|---|
   262→| 1 | **Veri Tazelik** | Son book güncellemesinden bu yana < 5 saniye | `STALE_DATA` |
   263→| 2 | **Spread Kontrolü** | Spread <= 10 bps | `SPREAD_TOO_WIDE` |
   264→| 3 | **VPIN Toksisite** | VPIN <= 0.8 | `VPIN_TOXIC` |
   265→| 4 | **Sıkıştırma Kontrolü** | Aktif sıkıştırma yok | `COMPRESSION_ACTIVE` |
   266→| 5 | **Kademeli Tasfiye** | Son 5 saniye içinde aktif cascade yok | `CASCADE_RECENT` |

   268→```ts
   269→interface RiskGateResult {
   270→  passed: boolean;
   271→  failedGate: string | null;   // 'STALE_DATA' | 'SPREAD_TOO_WIDE' | ...
   272→  details: Record<string, number>; // { staleMs: 3200, spreadBps: 4.2, vpin: 0.45, ... }
   273→}
   274→```
   275→
   276→Kapı sonuçları UI'da Panel 5'te (LEVELS) her CANDIDATE plan kartında gösterilir.

   310→interface ConfluenceResult {

   336→## 7. Net RR Hesaplayıcı (P0)
   337→
   338→**Öncelik:** Kritik — Gerçekçi risk-ödül oranı
   339→**Mevcut Referans:** `src/lib/engine/risk/tradePlanner.ts`, `src/lib/engine/fee-accounting.ts`
   340→
   341→Brüt RR'den aşağıdaki maliyetler düşülerek net RR hesaplanır:
   342→
   343→```ts
   344→interface NetRRCalculation {
   345→  grossRR: number;          // giriş öncesi ham RR
   346→  roundTripFeeBps: number;  // yapılandırılabilir, varsayılan 4 bps
   347→  avgSlippageBps: number;   // varsayılan 5 bps
   348→  fundingCostBps: number;   // saat başına maliyet * beklenen tutma süresi
   349→  netRR: number;            // sonuç
   350→}
   351→
   352→function calculateNetRR(
   353→  entry: number,
   354→  stopLoss: number,
   355→  takeProfit: number,
   356→  config: { roundTripFeeBps: number; avgSlippageBps: number; fundingRatePerHour: number; expectedHoldHours: number }
   357→): NetRRCalculation;
   358→```
   359→
   360→**Formül:**
   361→```
   362→netRR = grossRR - roundTripFeeBps - avgSlippageBps - (fundingRatePerHour * expectedHoldHours)
   363→```
   364→
   365→**Zorunlu koşul:** `netRR >= 2.0` — Aksi halde plan oluşturulmaz.

   369→## 8. Kitap Hızı (Book Velocity) (P1)
   370→
   371→**Öncelik:** Yüksek
   372→**Mevcut Referans:** `src/lib/engine/features/velocityFeature.ts`
   373→
   374→Order book güncellemeleri arasındaki değişimi izler:
   375→
   376→```ts
   377→interface BookVelocityResult {
   378→  bookVelScore: number;     // normalleştirilmiş hız skoru
   379→  notionalChange: number;   // toplam notional değişim
   380→  timeDeltaMs: number;      // güncelleme aralığı
   381→}
   382→```
   383→
   384→**Algoritma:**
   385→1. Her book güncellemesinde, önceki frame ile karşılaştır
   386→2. Aynı fiyat seviyesindeki miktar değişimlerinin notional değerini topla
   387→3. Zaman deltasına böl ve normalize et
   388→4. Sonuç `bookVelScore` olarak expose et
   389→5. Kullanılan alanlar: `prevBidPrices`, `prevBidQties`, `prevAskPrices`, `prevAskQties` (typed array)

   393→## 9. Çok Katmanlı OBI (Multi-Depth OBI) (P1)
   394→
   395→**Öncelik:** Yüksek
   396→**Mevcut Referans:** `src/lib/engine/features/obiFeature.ts`
   397→
   398→OBI hesaplaması 3 derinlikte yapılır:
   399→
   400→```ts
   401→interface MultiDepthOBI {
   402→  obi5: number;   // en iyi 5 seviye
   403→  obi10: number;  // en iyi 10 seviye
   404→  obi20: number;  // en iyi 20 seviye

   635→## 19. Gerçek Kelly Pozisyon Boyutlandırma (P1)
   636→
   637→**Öncelik:** Yüksek
   638→**Mevcut Referans:** `src/lib/engine/risk/positionSizer.ts`
   639→
   640→```ts
   641→interface KellyResult {
   642→  kellyFraction: number;       // W - (1-W)/R
   643→  halfKelly: number;           // kellyFraction / 2
   644→  confidenceAdjusted: number;  // halfKelly * (confidence / 100)
   645→  finalFraction: number;       // min(confidenceAdjusted, maxRiskPct)
   646→  positionSize: number;        // capital * finalFraction
   647→  winRate: number;             // W
   648→  rrRatio: number;             // R
   649→}
   650→```
   651→
   652→**Formül:**
   653→```
   654→kelly = W - (1 - W) / R
   655→halfKelly = kelly / 2
   656→confidenceAdjusted = halfKelly * (confidence / 100)
   657→finalFraction = min(confidenceAdjusted, maxRiskPct)   // hard cap
   658→positionSize = capital * finalFraction
   659→```
   660→
   661→- **Half-Kelly cap:** Kelly formülünün sonucu her zaman 2'ye bölünür
   662→- **Güven ayarlaması:** Sinyal güven skoru ile çarpılır (0-100 arası)
   663→- **Hard cap:** Hesaplanan değer, yapılandırılabilir maksimum risk yüzdesini (varsayılan %2) aşamaz
   664→

   698→
   699→```ts
   700→interface SignalDecayConfig {
   701→  [signalType: string]: number;  // decay rate (ms başına)
   702→}
   703→
   704→const DEFAULT_DECAY_CONFIG: SignalDecayConfig = {
   705→  'WALL': 0.0002,
   706→  'BID_WALL': 0.0002,
   707→  'ASK_WALL': 0.0002,
   708→  'SPOOFING': 0.002,       // hızlı çürür
   709→  'CASCADE_CHAIN': 0.003,  // hızlı çürür
   710→  'CASCADE_EXHAUSTED': 0.003,
   711→  'CVD_DIV': 0.003,        // hızlı çürür
   712→  'VOID': 0.0008,
   713→  'VOID_FILLING': 0.0008,
   714→  'ICEBERG': 0.0003,
   715→  'DEFAULT': 0.0005,
   716→};

   909→- `FILLING → FILLED`: Boşluk >= %80 doldu
   910→- Herhangi bir durum → `NONE`: **5 saniye** sonra otomatik sonlanma

  1091→## 31. Webhook Entegrasyonu (P2)
  1092→
  1093→**Öncelik:** Orta
  1094→
  1095→```ts
  1096→interface WebhookConfig {
  1097→  endpointUrl: string;      // hedef URL
  1098→  secret: string;           // HMAC imzalama secret
  1099→  dryRun: boolean;          // varsayılan: true (sadece log, gönderme)
  1100→}
  1101→```
  1102→
  1103→### 31.1 Gönderilen Olaylar
  1104→
  1105→| Olay | Tetikleyici |
  1106→|---|---|
  1107→| `plan.candidate` | Yeni CANDIDATE plan oluşturuldu |
  1108→| `plan.armed` | Kullanıcı planı onayladı (ARM) |
  1109→| `plan.cancelled` | Plan iptal edildi veya TTL sona erdi |
  1110→| `signal.new` | Yeni sinyal üretildi |
  1111→| `signal.verified` | Sinyal doğrulandı (VERIFIED) |
  1112→| `signal.missed` | Sinyal kaçırıldı (MISSED) |
  1113→| `fill.opened` | Paper pozisyon açıldı |
  1114→| `fill.closed` | Paper pozisyon kapandı (TP/SL) |
  1115→
  1116→### 31.2 İmza
  1117→
  1118→Her webhook gönderimi HMAC-SHA256 ile imzalanır:
  1119→```
  1120→signature = HMAC-SHA256(secret, JSON.stringify(payload))
  1121→Header: X-Bozok-Signature: <signature>
  1122→```
  1123→
  1124→### 31.3 Dry Run Modu
  1125→- `dryRun: true` (varsayılan) → Webhook gönderilmez, console'a loglanır
  1126→- `dryRun: false` → Gerçek HTTP POST gönderimi
  1127→- Settings panelinden (Panel 8) toggle ile değiştirilebilir
